# HwaFlow Confirmed-Bug Fixes — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the defects confirmed by the read-only audit without changing product behaviour beyond the bug being repaired.

**Architecture:** Six small, independent fix groups: (A) data integrity in the write path, (B) auth/session recovery, (C) honest UI state, (D) read-path correctness (pagination, counts, icons), (E) pipeline cost and failure handling, (F) SQL-policy and storage cleanup. Each task is self-contained and independently revertable. No new product surface is built.

**Tech Stack:** Next.js 16.4.2 (App Router), React 19.3, TypeScript 5.9, Supabase Postgres + Storage, Gemini via `lib/ai/gemini.ts`, Vitest (new).

**Spec:** The audit findings confirmed in this session's investigation. `docs/ARCHITECTURE.md` §6-§8 and §12 (decision log) are binding on data model and RPC policy.

## Global Constraints

- **Do not touch the user's uncommitted WIP.** 37 modified files exist (CSS redesign). Stage only files named in each task: `git add <explicit paths>`, never `git add -A` / `git commit -a`.
- **No new product surface.** `/admin/groups/[id]` rebuild, `is_active` enforcement, group switcher, and dashboard-query reshaping are explicitly **out of scope** (see Deferred).
- **RLS rules stay binding:** content writes are RPC-only; every new RPC is `SECURITY DEFINER` with `set search_path = ''` and re-checks the role; storage buckets stay private.
- **Migrations are additive.** Never edit an applied migration; add a new timestamped file. The user applies them (`supabase db push`); code must not assume they ran until confirmed.
- **Copy/tone:** user-facing errors keep the existing plain-language voice. No raw Postgres text to users.
- **No `any`, no `@ts-ignore`** — the repo currently has zero of both.
- **Every task ends green:** `npx tsc --noEmit --incremental false` exits 0 and `npm test` passes.

## Review Focus

- A chapter whose translations are re-extracted twice must keep human edits (the whole point of Task 1).
- A signed-in user with a missing `profiles` row must reach a usable page, never a redirect loop.
- A failed bubble save must not read "Saved".
- A chapter with >1000 `text_blocks` must render every bubble.
- A pipeline run must stop spending quota when the tab closes or the user cancels.
